# 예상·실행·비교

실행 전에 각 질문의 답을 한 줄씩 적어 두고, 실행 결과의 `PASS` 줄과 비교하세요.

1. Saga A가 요약을 게시한 뒤 검수에서 떨어집니다. 게시와 되돌림 사이에 독자가 글을 열면 무엇을 볼까요? 검수를 게시 앞으로 옮기거나(reorder), Saga가 끝날 때까지 요약을 감추면(hidden) 어떻게 될까요? 각 대응책이 대신 잃는 것은 무엇일까요?
2. 같은 글에 A가 게시하고, B가 게시해 성공한 뒤, A가 검수에서 떨어져 게시를 되돌립니다(되돌릴 때 "게시 전 값"으로 돌린다). 최종 요약은 누구의 것일까요?
3. 2와 같은데 A·B 둘 다 검수에서 떨어지고, A가 먼저 되돌린 뒤 B가 되돌립니다. "내 것일 때만 되돌리기"(casUndo)를 켜도 문제가 남을까요?
4. "글에 작업 중 표시"(postLock)를 켜면 2·3은 어떻게 될까요? 동시 실행에서 완료되는 Saga 수는 어떻게 달라질까요?
5. A가 글을 읽고 요약을 만드는 사이에 저자가 글을 고칩니다. 게시된 요약은 어느 버전의 글을 요약한 것일까요? 게시할 때 버전을 다시 확인하면(reread), 작업 중 표시로 수정을 막으면(postLock) 각각 누가 불편해질까요?
6. 한도 1,000인 저자의 600짜리 요청 A·B가 겹칩니다. A가 요약 생성 직전에 멈춘 사이에 B가 끝까지 갑니다. 시작할 때 예약하는 방식과, 잔량만 보고 끝날 때 더하는 방식에서 "A의 요약 생성이 실패할 때"와 "둘 다 성공할 때" 결과는 각각 어떨까요?

## 바꿔 보기

- `quota()`의 `quotaRow(w, 1000)`을 `quotaRow(w, 1200)`으로 바꾸면 예약 방식의 "A의 요약 생성이 실패할 때" 결과가 어떻게 달라질까요? 판정이 어디서 멈추는지 확인한 뒤 되돌리세요.

## 기록할 세 문장

- 실행 전에 나는 ___라고 예상했다.
- 실제 결과는 ___였다.
- Saga에 격리가 없다는 것은 ___이고, 대응책은 그 대신 ___를 내준다.
