# 실행 후 해설

1. 기준 실행은 100행에 Index Scan, 90000행에 Seq Scan을 선택했다. 인덱스 존재가 사용을 강제하지 않는다.
2. 원본 JSON 최상위 Plan의 Plan Rows / Actual Rows / Actual Loops를 읽는다. 기준 스캔의 loops는 모두 1이다.
3. 같은 100행의 기본 인덱스 경로는 버퍼 5회, 비교용 순차 스캔은 2041회였다. 후자는 99900행을 필터로 제외했다.
4. 최초 빈도 0.001이 변경 후에도 남아 예상100, 실제90010이 됐다. 일반 VACUUM만으로 값 분포 통계가 갱신되지 않았다.
5. ANALYZE 후 빈도0.9001, 예상90010으로 맞아지고 Seq Scan을 골랐다. 실행 버퍼 접근은 1998에서4043으로 늘었다.
   예상 개선과 실행 비용 개선은 별도이다. 전체 테이블 페이지와 일치 행이 있는 페이지의 범위가 다를 수 있다.
6. hit/read는 버퍼 접근이며 중복 접근 가능성이 있다. read는 OS 캐시에서 충족될 수 있다. 부모·자식 합산도 중복될 수 있다.
   캐시 상태·실행 순서·계측 오버헤드·결과 전송 차이를 통제하지 않은 숫자로 운영 응답 시간 개선을 주장하지 않는다.

이것은 코드가 확인한 결과이며 사용자의 숙지 여부를 대신하지 않는다.
