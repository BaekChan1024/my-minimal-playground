# 실행 후 비교

- INSERT 데이터는 네 컬럼 모두 같고 각 1만 행입니다. 인덱스 0·1·3개에서 WAL은 1,998,241 / 2,672,568 / 4,094,400바이트였습니다.
- heap은 모두 1,744,896바이트, 인덱스 합계는 0 / 245,760 / 827,392바이트였습니다. WAL은 로그 생성량, 파일 크기는 할당 공간입니다.
- id 하나의 조회는 Seq Scan 버퍼 213회, Index Scan 3회, Index Scan 3회였습니다. 추가 인덱스가 이 조회의 관측을 더 줄이지 않았으며 다른 조회는 별도 확인이 필요합니다.
- hot50은 HOT 10,000회, indexed50은 0회입니다. 같은 페이지 여유뿐 아니라 바꾼 컬럼이 B-tree 인덱스에서 참조되는지도 중요합니다.
- dense100은 비인덱스 score를 바꿨지만 다른 페이지 갱신 10,000회, HOT 0회였습니다. id 인덱스 파일도 커졌습니다.
- fillfactor 50의 초기 heap은 3,563,520바이트로 100보다 큽니다. 이 여유가 첫 갱신의 heap 확장을 피하게 했지만 공짜 공간은 아닙니다.
- WAL은 문장 실행 범위의 기록입니다. FPI를 포함하고 커밋 지연이나 실제 디스크 처리량은 측정하지 않았습니다. 단일 전체 갱신을 반복 쓰기·동시 부하의 정상 상태로 일반화할 수 없습니다.

위 내용은 자동 실습의 관측이며 사용자 학습 완료를 대신하지 않습니다. 코드의 여섯 검증과 별도로 자신의 예상과 결과를 비교하세요.
