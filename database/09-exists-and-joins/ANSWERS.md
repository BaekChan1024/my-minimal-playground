# 실행 후 해설

1. 둘 다 true였다. COUNT의 Index Only Scan은 50,000행을 전달했고 EXISTS의 Seq Scan은 첫 일치 1행에서 멈췄다. 버퍼 접근은 44와 2였다.
2. 둘 다 false였다. 인덱스가 있으면 두 쿼리 모두 빈 탐색으로 버퍼 접근 2, 없으면 100,000행을 필터로 제외하고 버퍼 접근 2,128이었다. 스캔 출력 0은 읽기 0을 뜻하지 않는다.
3. JOIN은 100,000행, 고객42번은 100번 나온다. DISTINCT와 EXISTS는 각각 정확히 고객1~1,000을 한 번씩 반환했다. 주문이 없는 고객10명은 제외됐다.
4. 달랐다. DISTINCT + JOIN은 91, EXISTS는 2,026이었다. 반복 인덱스 탐색은 같은 블록을 다시 방문한다. 이 숫자로 시간 우열을 주장할 수 없다. 내부 Actual Rows=0.99는 1,010회 탐색의 반올림된 평균이다.
5. 인덱스를 제거하자 orders 100,000행을 스캔하고 customer_id 1,000개로 집계한 뒤 Hash Join(Inner)했다. 최종 고객 목록은 같았고 버퍼 접근은 2,133이었다.
6. true다. GROUP BY/HAVING 없는 COUNT는 빈 입력에서도 값0인 한 행을 반환한다. EXISTS는 그 결과 행의 존재를 검사한다. SELECT 1로 원본 행 존재를 확인하면 false다.

이는 자동 실습의 관측이며 사용자 숙지 확인을 대신하지 않습니다.
