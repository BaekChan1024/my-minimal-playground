# 실행 후 비교할 해설

1. Consumer 1개가 파티션 3개 모두를 담당할 수 있습니다. 이 코드는 한 스레드가 순차 처리합니다.
2. 같은 그룹의 안정 상태에서는 파티션 담당을 나눕니다. 한 파티션이 그룹의 두 멤버에 동시에 할당되지 않습니다.
3. 이 토픽·RangeAssignor 조건에서는 각각 1개씩입니다.
4. 파티션이 3개여서 한 멤버는 할당이 없습니다. 단, 특정 이름의 Consumer가 항상 쉬는 것은 보장하지 않습니다.
5. audit에 커밋이 없고 earliest이므로 처음부터 읽습니다. 같은 로그를 공유하지만 커밋은 그룹별입니다.
6. 로그는 그대로이고 담당자만 바뀝니다. 이번 실험은 기존 데이터를 모두 커밋한 다음 정상 종료하므로 저장된 위치에서 이어갑니다.
7. 같은 키가 같은 파티션으로 향하므로 한 멤버가 9개를 처리합니다. 나머지는 다른 파티션을 맡고 있어도 새 데이터가 없습니다.

## 관측한 분배

| 같은 그룹의 멤버 수 | 파티션 수 분배(정렬) | 균등 합성 입력 9개의 처리 건수(정렬) |
|---|---|---|
| 1 | 3 | 9 |
| 2 | 1, 2 | 3, 6 |
| 3 | 1, 1, 1 | 3, 3, 3 |
| 4 | 0, 1, 1, 1 | 0, 3, 3, 3 |

마지막 단일 키 단계는 0, 0, 9입니다. 한 파티션에 몰린 일을 Consumer 수만 늘려 쪼갤 수는 없습니다.
서로 다른 파티션의 전체 실행 순서는 이 표로 보장되지 않습니다.

## 조건 변경 해설

마지막 단계를 false로 바꾸면 세 키로 나누어 보내므로 세 담당자가 읽습니다.
따라서 active == 1 검증이 실패하는 것이 의도한 결과입니다. 실제 실행 출력으로 비교하세요.
원래 true로 되돌린 뒤 정상 검증과 비교합니다.

이번 성공은 실험 조건에서 각 그룹이 중복 없이 54개를 관측했다는 뜻입니다.
장애 구간에서도 exactly-once가 보장되거나 Consumer를 세 배로 늘리면 속도도 세 배가 된다는 뜻이 아닙니다.
