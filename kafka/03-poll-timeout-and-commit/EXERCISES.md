# 실행 전에 예상하기

1. A가 offset 0을 읽어 효과 카운터를 1로 만든 후 커밋 없이 poll을 멈춘다. B가 같은 그룹의 담당자가 되면 무엇을 읽을까?
2. B가 재전달 레코드의 효과를 반영하고 커밋했다. A가 뒤늦게 커밋하면 성공할까? 실패한다면 A가 이미 반영한 효과도 사라질까?
3. A가 효과를 반영하고 committed=1까지 저장한 다음 멈추면 B의 결과는 어떻게 달라질까?

`./play-kafka-03`으로 두 조건을 실행하고 `newReads`, `effects`, `committed`, `oldLateCommitFailed`를 예상과 비교한다. `committed=null`은 0을 저장했다는 뜻이 아니라 저장된 커밋이 없다는 뜻이다.

첫 조건의 `effects=2`를 보고 Kafka 로그 자체에 레코드가 두 개 쌓였다고 말할 수 있는지 설명해 본다. Producer는 한 번만 전송한다.

코드 변경 연습(별도로 실행 검증하지 않은 제안): 실습용 `max.poll.interval.ms`를 2000에서 4000으로 바꾸고 재실행한다. 인계까지 기다리는 느낌은 달라질 수 있지만 두 조건의 결과가 왜 같아야 하는지 먼저 설명한다. 전체 대기 상한을 넘을 정도로 값을 늘리면 실습이 timeout으로 실패할 수 있다. 이 연습은 성능 측정이 아니다.
