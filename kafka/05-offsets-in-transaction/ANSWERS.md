# 해설

1. 첫 Consumer의 position은 1이지만 저장된 커밋은 없습니다. 새 그룹의 earliest 설정에 따라 offset 0을 다시 읽습니다. 자동 커밋은 꺼져 있습니다.
2. 입력 커밋은 없고 RC 출력도 0건입니다. 오프셋 등록 호출만으로 커밋이 완료되지 않습니다. RU에는 abort된 출력이 보입니다.
3. 처리 시도는 2회, RC 출력은 1건입니다. 중단된 첫 시도까지 함수 실행 횟수에서 지워지지는 않습니다.
4. 새 Consumer의 실제 P0 할당, position=1, inputEnd=1과 poll 반환이 비어 있음을 함께 확인합니다. 실습은 그 전에 입력 offset 0의 정체성과 실제 소비를 검증합니다.
5. 커밋은 다음 읽기 위치입니다. 입력과 출력은 다른 토픽의 로그이므로 출력 오프셋은 입력 재시작 위치가 아닙니다. 실제 배치의 nextOffsets를 사용합니다.
6. 되돌려 주지 않습니다. 실습은 abort 직후 position=1을 확인합니다. Consumer를 새로 만들어 저장된 그룹 커밋에서 재개하는 방법을 검증했으며 같은 객체의 seek/재시도 루프는 구현하지 않았습니다.
7. 말할 수 없습니다. 이번 출력은 Kafka 트랜잭션의 범위이며 DB나 HTTP는 실행하지 않았습니다. attempts는 Java 정수 모델입니다.

실습의 정상 종료/재시작은 프로세스 강제 종료가 아닙니다. 응답 유실·fencing·리밸런스 실패·Producer 재시작 복구도 별도 검증 대상입니다.
