# 결과 해설

1. old로 회귀합니다. 두 ID는 다른 사건이라 둘 다 Inbox를 통과합니다.
2. new 유지, E1은 STALE. 처리 판단을 완료했으므로 Inbox에는 남깁니다.
3. 같은 eventId는 Inbox에서 먼저 DUPLICATE 처리합니다.
4. 삭제 버전3을 보존하면 낮은 버전을 거부하고 visible=0을 유지합니다.
5. 미처리 ID의 오래된 입력은 기존 버전 행이 없으므로 INSERT되어 부활할 수 있습니다. 실습용 새 ID로 버전 보호 자체를 시험했으며 정상 재처리 때 ID를 바꾸라는 뜻은 아닙니다.
6. 7이 됩니다. 의도한 10에서 +3을 잃었습니다. 전체 스냅샷 규칙을 변화량에 그대로 적용하면 안 됩니다.

E1→E2로 바꾸면 두 정책 모두 new가 됩니다. 정상 순서의 성공만으로 역순 안전성을 입증할 수 없는 이유입니다.
