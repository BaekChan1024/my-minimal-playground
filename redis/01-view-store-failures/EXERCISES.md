# 예상·실행·비교

실행 전에 각 질문의 답을 한 줄씩 적어 두고, 실행 결과의 `PASS` 줄과 비교하세요.

1. Redis가 1초 동안 죽어 있는 사이 조회 요청은 얼마나 걸릴까요? 연결이 끊긴 동안 명령을 바로 거부할 때와 Lettuce 기본값(재연결까지 쌓아 둠)일 때 같은 1초에 처리하는 요청 수는 어떻게 다를까요? Redis가 다시 뜬 직후에는 바로 세어질까요?
2. 명령 타임아웃이 300ms이면 Redis가 250ms씩 늦을 때 조회 한 번은 최대 몇 ms 걸릴까요? 400ms씩 늦을 때 첫 조회는 실패합니다. 지연이 사라진 뒤 같은 세션으로 다시 조회하면 세어질까요?
3. 키를 만든 직후 Redis를 `kill -9` 하면, AOF 없음 / `everysec` / `always`에서 키가 몇 개 남을까요? `everysec`는 "1초를 잃을 수 있다"고 하는데 이 실험에서도 그럴까요? `always`의 대가는 무엇일까요?
4. 메모리가 꽉 찼을 때 `allkeys-lru`, `volatile-ttl`, `noeviction`은 각각 무엇을 지우거나 거부할까요? 지워진 중복 제거 키의 세션이 다시 오면? 순위 키는 살아남을까요?
5. Redis와 DB가 왕복 5ms 거리에 있으면 postgres 방식과 redis 방식의 조회 기록 시간 차이는 얼마일까요? 조회 한 번에 각각 몇 번 왕복할까요? Lua 스크립트로 묶으면?
