# 실행 후 비교

1. 참조 실행에서 희귀는 Seq Scan, 희귀표식은 BitmapOr와 GIN을 사용했습니다. 결과 수는 모두 9였습니다(5만 행). LIKE 패턴에서 추출할 trigram과 결과 희소성은 다른 조건입니다.
2. 후보 행을 찾는 것과 날짜/id 정렬은 다릅니다. GIN 단계에서는 Sort가 남았습니다.
3. 정렬 대응 인덱스가 있는 검색 안내 list는 20개를 찾고 멈췄지만 count는 23,530개 전체 결과를 계산했습니다.
4. %와 _는 wildcard이므로 리터럴 입력은 escape해야 합니다. 바인딩은 SQL 값 전달의 문제이고 패턴 의미는 별도입니다.
5. title='red', excerpt='blue'가 연결 문자열에서는 red blue와 일치해 원래 필드별 검색 의미를 바꿀 수 있습니다. 실습은 경계를 유지한 OR의 결과를 확인합니다.

본문 검색 속도를 형태소 분석·오타 교정·관련도 품질 개선과 혼동하지 않습니다. API 전체의 categoryMap/statistics/전송 비용, 실제 운영 분포, 쓰기 부하는 측정하지 않았습니다.
