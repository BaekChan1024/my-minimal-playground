# 먼저 예상하기

1. A와 B가 같은 제목을 읽고 A가 먼저 커밋합니다. 버전 없는 B의 UPDATE는 실패할까요, A를 덮어쓸까요?
2. @Version이 있고 둘 다 0을 읽었다면 B의 SQL WHERE 조건과 최종 결과는 무엇일까요?
3. 두 편집 화면이 버전0을 열었지만 저장 요청은 순서대로 온다면 @Version만으로 B의 오래된 화면을 알 수 있을까요?
4. DB 잠금이 B를 기다리게 하면 B의 편집 내용까지 최신으로 바뀔까요?
5. 행 잠금이 잡힌 동안 READ COMMITTED의 일반 SELECT도 반드시 기다릴까요?
6. 충돌을 받자마자 최신 version으로 바꿔 같은 제목을 재전송하면 누구의 수정을 보존할까요?

추가 조건 변경: staleRequest에서 B의 expected 값을 0에서 1로 바꾸고 비교를 켜면 정상 저장돼야 합니다. 단, 이것은 사용자가 최신 내용에 동의한 상황을 모사합니다. 숫자만 자동 교체하는 재시도 정책은 아닙니다. 수정 후 고정 검증기의 기대값이 달라지는 이유를 설명해 보세요.
